# 강사의 LO 인스턴스 편집에 대한 Webhook 이벤트

Adobe Learning Manager은 강사 주도 강의 세션과 같은 학습 객체(LO) 인스턴스가 수정되면 외부 시스템에 이를 알리는 Webhook 이벤트를 제공합니다. 이전에는 책임자 또는 작성자가 LO 인스턴스를 수정한 경우에만 이러한 이벤트가 트리거되었습니다. 이제 강사가 세션 세부 정보를 편집할 때도 Webhook 이벤트가 트리거됩니다.

이러한 이벤트를 사용하여 전자 메일 서비스, 일정, 보고 도구 또는 분석 플랫폼과 같은 외부 시스템을 강사 변경 사항으로 최신 상태로 유지할 수 있습니다. 예를 들어 세션 시간이 변경되면 학습자에게 통지할 수 있습니다.

강사 편집은 기존의 학습 객체 인스턴스 수정 이벤트를 사용하기 때문에 새로운 이벤트 유형이 도입되지 않습니다.

>[!NOTE]
>
>강사 편집은 활성 Webhook가 학습 개체 인스턴스 수정 이벤트를 구독하는 경우에만 Webhook을 트리거합니다. [통합 관리자로서 Webhook을 만들고 관리](/help/migrated/integration-admin/feature-summary/webhooks.md#create-manage-webhooks)하는 방법에 대해 알아봅니다.

## 지원되는 강사 편집

강사가 다음 세션 세부 정보를 편집하면 Webhook 이벤트가 트리거됩니다.

* 세션 타이밍

* 점수

* 표준 시간대

* 장소

* 등록 제한

* 대기자 명단 제한

* 제출 허용

## Webhook 페이로드 구조

각 Webhook 요청에는 다음과 같은 최상위 구조가 포함됩니다.

```json
{
  "accountId": 1234,
  "events": [
    {
      "eventId": "121da98-ab8d-43e9-b671-e79131cd69dc",
      "eventName": "LEARNING_OBJECT_INSTANCE_MODIFICATION",
      "timestamp": "2024-11-08T03:49:52.000Z",
      "eventInfo": "1235603297000-040649-741781-0",
      "data": {
        "loInstanceId": "course:12324298_14453691",
        "loId": "course:12324298",
        "loType": "course"
      }
    }
  ]
}
```

LO 인스턴스를 수정하는 사람에 관계없이 동일한 구조가 사용됩니다. 강사, 책임자 또는 작성자가 변경했는지 여부를 페이로드로 나타내지 않습니다.

강사가 시간대, 등록 제한 또는 대기자 명단 제한과 같은 세션 세부 정보를 변경하면 Webhook는 이 이벤트를 리스너 URL로 전송합니다. 이 이벤트를 사용하여 최신 세션 세부 정보를 검색하고 학습자에게 알리거나 외부 시스템을 업데이트할 수 있습니다.

## 업데이트된 세션 세부 정보 검색

Webhook 이벤트는 수정된 LO 인스턴스를 식별합니다. 업데이트된 세션 세부 정보를 가져오려면 다음 이벤트에서 `loId`을(를) 사용하여 Learning Manager 공개 API(Prime API)를 호출하십시오.

```http
GET /primeapi/v2/learningObjects/{loId}
```

응답에서 `loInstanceId`과(와) 일치하는 인스턴스를 찾은 다음 시스템에 저장된 데이터와 비교합니다.

## Webhook 이벤트와의 통합 빌드

다음 Webhook 이벤트를 사용하여 다음을 수행할 수 있습니다.

* 날짜, 시간, 시간대 또는 장소 변경과 같은 세션 세부 정보가 변경될 때 외부 전자 메일 또는 메시지 서비스를 통해 학습자 알림을 보냅니다.

* 외부 달력, 보고 또는 분석 시스템과 세션 데이터를 동기화합니다.

* 세션의 등록 제한 또는 대기자 명단 제한이 수정되었을 때 용량 변경을 추적합니다.

* LO 및 인스턴스 식별자와 함께 `eventId`, `timestamp` 및 `eventInfo`을(를) 로깅하여 감사 추적을 유지합니다.

Webhook 처리기는 최소한 다음 작업을 수행해야 합니다.

* 페이로드의 유효성을 검사하고 `events[]`을(를) 구문 분석합니다.

* `eventName`을(를) 사용하여 학습 개체 인스턴스 수정 이벤트를 식별합니다.

* `loId` 및 `loInstanceId`을(를) 사용하여 시스템에서 해당 레코드를 찾고 공용 API를 호출하여 현재 세션 세부 정보를 검색합니다.

* 동일한 이벤트가 두 번 이상 전달되는 경우 중복 처리를 방지하려면 `eventId`을(를) 사용하십시오.

강사, 책임자 및 작성자가 편집한 내용에 대해 동일한 이벤트가 전송되므로, 통합이 이전보다 더 자주 수신될 수 있습니다. 알림을 보내기 전에 검색된 세션 세부 정보를 시스템의 데이터와 비교합니다. 그러면 학습자는 관련 세부 정보가 변경될 때만 알림을 받습니다.
