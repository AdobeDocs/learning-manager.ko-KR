# ALM-Workfront 취소/업데이트 트리거

## 개요

Adobe Learning Manager(Learning Manager)는 이제 Workfront의 변경 사항을 기반으로 강사 주도 및 가상 강사 주도(ILT/VILT) 세션을 취소하고 다시 활성화할 수 있습니다. 조직에서 Workfront으로 세션을 예약하고 Learning Manager로 Workfront 마이그레이션을 통해 해당 세션을 Learning Manager로 가져오는 경우, 마이그레이션 데이터에서 각 세션의 상태를 활성 또는 취소됨으로 설정할 수 있습니다. 그러면 Learning Manager는 책임자가 사용자 인터페이스에서 세션을 취소한 것처럼 변경 사항을 적용합니다.

마이그레이션을 통해 세션을 취소하는 것은 Learning Manager 사용자 인터페이스에서 해당 세션을 취소하는 것과 동일한 작업을 수행합니다. 한 가지 중요한 차이점은 다시 활성화라는 것입니다. [취소된 세션 다시 활성화](#reactivate-a-cancelled-session)에 설명되어 있습니다.

### 요구 사항

날짜 및 시간, 강사, 위치 또는 링크, 용량 등의 세션 업데이트는 이미 마이그레이션을 통해 Workfront에서 Learning Manager로 전달됩니다. 취소하지 않았습니다. Workfront에서 세션이 취소되면 Learning Manager에서 알 수 없는 문제가 발생하여 다음과 같은 문제가 발생했습니다.

* 학습자는 더 이상 실행되지 않는 세션에 등록된 상태를 유지하게 되어 혼란과 노쇼가 발생했습니다.
* 책임자는 Learning Manager에서 수동으로 취소를 반복해야 했습니다.
* Workfront과 Learning Manager가 동기화되지 않아 Workfront이 스케줄링 시 소스로서의 역할을 제대로 수행하지 못했습니다.

### 작동 방식

1. 배달 관리자가 Workfront에서 세션을 취소합니다.
1. 마이그레이션 데이터의 세션 행에는 취소됨으로 설정된 새 세션 상태 열이 포함됩니다.
1. 시스템 관리자는 API를 통해 마이그레이션을 실행합니다.
1. Learning Manager는 일치 세션을 취소됨으로 표시하고 사용자 인터페이스에서 취소한 것과 동일한 알림을 보냅니다.

>[!NOTE]
>
>이 기능은 두 번째 실시간 통합 경로를 추가하지 않고 기존 마이그레이션 프로세스를 확장합니다.

## 사용 사례

Workfront에서 시작되는 취소에는 다음 역할이 관련되어 있습니다.

### 관련 역할

| 역할 | 설명 |
|---|---|
| 배달 관리자 | 세션 취소를 포함하여 Workfront의 교육 일정을 예약하고 관리합니다. 전달 관리자는 Learning Manager 사용자 인터페이스를 사용하지 않습니다. 마이그레이션은 취소가 Learning Manager에 도달하는 유일한 경로입니다. |
| 시스템 관리자 | API를 통해 마이그레이션을 실행합니다. 이 역할은 Workfront-to-Learning Manager 파이프라인을 운영하며 배달 관리자 및 Learning Manager 관리자와 별개입니다. |
| 책임자 | Learning Manager 사용자 인터페이스에서 강의 및 세션 데이터를 관리합니다. 관리자는 Workfront의 변경 사항에 대한 알림을 받은 후 더 이상 수동으로 세션을 취소할 필요가 없습니다. |
| 작성자 | Learning Manager 사용자 인터페이스에서 강의 및 세션 콘텐츠를 소유합니다. |
| 강사 | 세션에 할당됩니다. 강사는 올바른 세션 상태를 보고 자신이 지시하는 세션이 취소되면 알림을 받습니다. |
| Prime에서 | Learning Manager를 통해 세션에 등록됩니다. 학습자는 세션이 취소되면 즉시 알림을 받습니다. |

### 일반적인 시나리오

| 시나리오 | 사용자의 작업 | 결과 |
|---|---|---|
| 예를 들어 리소스를 사용할 수 없거나 공급업체에 문제가 있기 때문에 Workfront에서 세션이 취소됩니다. | 세션의 마이그레이션 행에서 세션 상태를 취소됨으로 설정하고 마이그레이션을 실행합니다. | Learning Manager에서 세션이 취소되고 영향을 받는 사용자에게 알림이 전송됩니다. |
| Workfront의 활성 세션 변경에 대한 세부 정보입니다. | 마이그레이션 행에 변경된 값을 포함합니다. 세션 상태를 활성으로 설정하거나 비워 둡니다. | 세션이 업데이트됩니다. Learning Manager에서 세션 업데이트 이메일을 전송합니다. |
| 취소된 세션은 Workfront에서 복원됩니다. | 마이그레이션 행에서 세션 상태를 활성으로 설정하고 마이그레이션을 실행합니다. | 세션이 활성 상태가 되며 수정 및 다시 취소할 수 있습니다. |
| 상태를 활성으로 설정하지 않고도 취소된 세션에 대해 업데이트된 세부 정보가 전송됩니다. | 사용자가 조치를 취할 필요는 없습니다. | 세션이 취소된 상태로 유지되고 행에서 유효성 검사 오류가 반환되며 세부 정보가 변경되지 않습니다. |
| 마이그레이션 행에는 세션 상태가 포함되지 않습니다. | 열을 비워 두거나 생략합니다. | Learning Manager에서 세션의 현재 상태는 변경되지 않습니다. |

## 주요 기능

* **세션 상태 열.** 마이그레이션 스키마에는 활성 및 취소됨 을 지원하는 선택적 세션 상태 필드가 포함되어 있습니다.
* **마이그레이션을 통한 취소** 행의 상태가 취소됨 이면 Learning Manager의 일치 세션이 취소됩니다. Learning Manager는 마이그레이션이 세션을 생성하고 업데이트하는 데 이미 사용하는 것과 동일한 일치 키를 사용합니다.
* **Learning Manager에서 수동 작업이 없습니다.** 관리자는 사용자 인터페이스에서 세션을 다시 취소할 필요가 없습니다.
* **사용자 인터페이스에서 취소하는 것과 같은 동작입니다.** 등록 처리, 학습자 대상 가시성, 보고, 감사 추적 및 알림이 사용자 인터페이스에서의 취소와 일치합니다.
* **다시 활성화.** 마이그레이션 데이터에서 상태를 명시적으로 설정하여 취소된 세션을 다시 활성으로 설정할 수 있습니다.
* **취소된 세션에 대한 보호.** 행이 명시적으로 상태를 활성으로 설정하지 않는 한 마이그레이션은 취소된 세션의 세부 정보를 변경하지 않습니다.
* **이전 버전과의 호환성** 상태 열은 선택 사항이므로 기존 마이그레이션 파일은 변경 없이 계속 작동합니다.
* **알림을 완료합니다.** 학습자, 강사, 책임자, 작성자 및 관리자는 사용자 인터페이스에서 취소 시 이와 동일한 취소 전자 메일을 받습니다.

## 세션 상태

Learning Manager의 모든 세션은 두 가지 상태 중 하나입니다.

| 상태 | 의미 |
|---|---|
| 활성 | 기본 상태입니다. 세션이 실시간으로 진행되며 학습자는 세션에 등록하고 참석할 수 있습니다. |
| 취소됨 | 세션이 취소되었습니다. 등록된 학습자, 책임자, 작성자 및 관리자는 사용자 인터페이스에서 취소할 수 있다는 알림을 받습니다. |

### 마이그레이션에 대한 상태 전환 규칙

다음 표에서는 마이그레이션 행을 처리할 때 수행되는 작업을 보여 줍니다. Learning Manager는 마이그레이션이 생성 및 업데이트에 이미 사용하는 일치하는 키를 사용하여 세션을 식별합니다.

| Learning Manager의 현재 상태 | 마이그레이션 행의 세션 상태 | 결과 |
|---|---|---|
| 세션이 없습니다. | 활성 또는 공백 | 세션이 활성 상태로 생성됩니다. |
| 활성 | 활성 또는 공백 | 세션은 활성 상태로 유지됩니다. 행의 변경된 값이 적용됩니다. |
| 활성 | 취소됨 | 세션이 취소되고 알림이 전송됩니다. |
| 취소됨 | 취소됨 | 행을 건너뜁니다. 취소된 세션은 다시 취소할 수 없습니다. |
| 취소됨 | 활성 | 세션이 다시 활성화됩니다. 행의 변경된 값이 적용됩니다. |
| 취소됨 | 비어 있음 | 세션 유지가 취소되었습니다. 행의 값이 변경된 경우 유효성 검사 오류가 반환되고 세부 정보가 변경되지 않습니다. |

### 세션 상태 열에 대한 규칙

* 이 열은 모든 행에서 선택 사항입니다.
* 열이 비어 있으면 세션이 활성으로 업데이트됩니다.
* 열에 명시적으로 활성 이 표시된 경우에만 마이그레이션을 통해 세션이 다시 활성화됩니다.

세션 상태 열에서 다음 값 중 하나를 사용합니다.

* `state = Active`
* `state = Cancelled`

>[!NOTE]
>
>정확한 열 머리글과 허용되는 값을 확인하고 있습니다. 마이그레이션 설명서에서 지정한 이름을 사용합니다.

## 취소된 세션 업데이트

마이그레이션을 통해 취소된 세션의 세부 정보를 업데이트할 수 없습니다. 취소된 세션의 행에 변경된 값이 포함되어 있고 상태가 활성으로 설정되지 않은 경우 Learning Manager는 검증 오류를 반환하고 세션을 취소된 상태로 두며 변경된 세부 정보를 적용하거나 저장하지 않습니다. Learning Manager는 시도 시 세션 업데이트 전자 메일을 보내지 않습니다.

### 마이그레이션을 사용하여 세션 취소

Workfront에서 세션이 취소되어 Learning Manager가 변경 사항을 반영하도록 하려는 경우 이 절차를 따르십시오.

**시작하기 전**

* Workfront에서 Learning Manager로의 마이그레이션을 통해 가져온 Learning Manager에 세션이 이미 있습니다.
* 마이그레이션이 세션을 식별하는 데 사용하는 일치 키를 알고 있습니다.

1. **Workfront**&#x200B;에서 세션을 취소합니다.
1. 마이그레이션하는 데 사용하는 세션 CSV 파일에서 세션의 행을 찾습니다. 일치하는 키가 세션을 만들 때 사용한 키와 동일한지 확인합니다.
1. 세션 상태 열에 **취소됨**&#x200B;을(를) 입력합니다.
1. API를 통해 마이그레이션을 실행합니다.
1. Learning Manager에서 세션이 취소되었는지 확인합니다.

Learning Manager는 세션을 취소된 것으로 표시하고, 사용자 인터페이스에서의 취소와 마찬가지로 등록된 학습자를 처리하고 취소 알림을 전송합니다. Learning Manager 사용자 인터페이스에 필요한 조치가 없습니다.

>[!NOTE]
>
>세션이 이미 취소된 경우 Learning Manager에서 해당 행을 건너뜁니다.

### 활성 세션 업데이트

활성 세션의 경우 기존 마이그레이션 업데이트 동작을 계속 사용할 수 있습니다. 세션 상태를 활성으로 설정하거나 비워 두고 변경된 값을 행에 포함합니다. 마이그레이션 파이프라인을 통해 날짜 및 시간, 강사, 위치 또는 링크, 용량 등의 세부 정보를 계속 업데이트할 수 있습니다.

활성 은 기존의 만들기 및 업데이트 동작을 유지합니다. Cancelled는 세션 CSV 마이그레이션을 통해 사용자 인터페이스가 제공하는 것과 동일한 세션 취소를 호출합니다.

### 취소된 세션 재활성화

취소된 세션은 상태를 명시적으로 활성으로 설정한 경우에만 활성 상태로 돌아갑니다. 마이그레이션을 통하거나 사용자 인터페이스에서 편집하여 세션을 다시 활성화할 수 있습니다.

1. 세션 CSV 파일에서 취소된 세션의 행을 찾습니다. 일치하는 키가 세션을 만들 때 사용한 키와 동일한지 확인합니다.
1. 세션 상태 열에 활성 을 입력합니다.
1. (선택 사항) 날짜 및 시간, 강사, 위치나 링크 또는 능력과 같이 변경할 행의 다른 값을 갱신합니다.
1. API를 통해 마이그레이션을 실행합니다.

세션이 활성 상태가 되고 세부 정보를 수정할 수 있습니다. 마이그레이션을 통해 또는 사용자 인터페이스를 통해 다시 활성화된 세션은 두 경로 중 하나를 통해 다시 취소할 수 있습니다.

>[!IMPORTANT]
>
>상태를 활성으로 설정하지 않고 취소된 세션에 대해 업데이트된 세션 세부 정보를 전송하면 세션이 취소된 상태로 유지되고 행이 검증 오류를 반환합니다.

## 알림

마이그레이션을 통해 세션이 취소된 경우 Learning Manager는 사용자 인터페이스에서 취소를 위해 보내는 모든 전자 메일을 보냅니다. 수신자 적용 범위는 줄어들지 않으며 내용도 동일한 템플릿을 사용하므로 수신자는 취소가 시작된 방법을 알 수 없습니다.

세션에 해당하는 수신자는 다음과 같습니다.

| 수신자 | 알림 |
|---|---|
| 학습자 | 세션에 등록한 학습자에게 세션이 취소되었다는 메시지가 표시됩니다. |
| 강사 | 세션에 할당된 강사에게 취소 알림이 전송됩니다. |
| 관리자 | 관리자는 취소 알림을 받습니다. |

### 취소된 세션 전자 메일

취소된 세션은 세션 업데이트 전자 메일을 생성하지 않습니다. 세션이 취소되는 동안 날짜 및 시간, 강사, 위치 또는 링크 및 용량을 변경해도 세션 업데이트 전자 메일은 트리거되지 않습니다. 취소 및 재활성화 알림만 취소된 세션에 적용됩니다.

## 고려 사항 및 제한 사항

* 이 기능은 마이그레이션을 사용하므로 마이그레이션이 실행될 때 Workfront에서 수행한 취소는 Learning Manager에 전달됩니다. Webhook 기반 실시간 취소는 지원되지 않습니다.
* 마이그레이션은 취소된 세션의 세부 정보를 변경할 수 없습니다. 변경하려면 먼저 상태를 활성으로 설정합니다.
* 세션 상태 열은 선택 사항입니다. 생략한 행에서는 세션의 상태가 변경되지 않습니다.
* 이 기능은 기존 마이그레이션 통합을 확장합니다. 두 번째 실시간 통합 경로가 추가되지 않습니다.
* 마이그레이션 일정 또는 트리거는 조직에서 사용하는 도구에 따라 다릅니다. 이 설명서에서는 고정 일정을 정의하지 않습니다.
* 배달 관리자는 Workfront에서만 작업합니다. 세션을 취소하기 위해 Learning Manager 사용자 인터페이스에 액세스하지 않아도 됩니다.

## 성공 측정값

| 측정 | 대상 |
|---|---|
| 관리자 또는 고객 지원에서 수동으로 복제한 취소 | 출시 후 한 번의 전체 릴리스 주기 내에 0으로 감소되었습니다. |
| Learning Manager에 반영된 Workfront 취소 | 취소 이벤트의 100%가 한 마이그레이션 주기 내에서 처리됩니다. |
| 사용자 인터페이스와 마이그레이션 취소 사이의 알림 패리티 | 수신자 적용 범위의 0개 간격(관리자, 작성자, 관리자 및 학습자)과 취소된 세션에 대한 0개의 불필요한 업데이트 전자 메일. |

## 문제 해결

| 문제 | 예상 또는 가능한 원인 | 액션 |
|---|---|---|
| 세션은 Workfront에서 취소된 후에도 활성 상태로 유지됩니다. | 마이그레이션이 아직 취소를 처리하지 않았거나 마이그레이션 행에 명시적 취소됨 상태가 없습니다. | 마이그레이션 입력 및 처리 결과를 확인합니다. |
| 취소된 세션의 세부 정보는 변경되지 않습니다. | 세션이 계속 취소된 상태에서 예상된 동작입니다. | 상태를 활성으로 설정하여 세션을 다시 활성화한 다음 변경 사항을 적용합니다. |
| 취소된 세션에 대해 세션 업데이트 전자 메일이 전송되지 않습니다. | 예상된 동작입니다. 취소된 세션에서 일반 업데이트 이메일이 표시되지 않습니다. | 세부 정보 전용 업데이트 대신 취소 및 재활성화 수명 주기를 사용합니다. |
| 취소 행을 건너뜁니다. | Learning Manager의 일치 세션이 이미 취소되었습니다. | 추가로 취소할 필요는 없습니다. 다시 활성 상태로 돌아가려면 먼저 세션을 다시 활성화하십시오. |
| 수신자가 사용자 인터페이스 취소와 동일한 취소 이메일을 받았습니다. | 예상된 동작입니다. 마이그레이션 취소는 사용자 인터페이스와 일치하도록 설계되었습니다. | 조치가 필요하지 않습니다. |
| 세션 상태가 비어 있는 경우 동작은 명확하지 않습니다. | 소스 요구 사항이 빈 상태 처리와 충돌합니다. | 전환에 빈 상태를 사용하기 전에 릴리스 동작을 확인합니다. |
