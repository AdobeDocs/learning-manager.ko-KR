# NRPS에 대한 LTI 지원

## 개요

Adobe Learning Manager은 LTI(Learning Tools Interoperability) 1.3 도구 역할을 하는 경우 NRPS(이름 및 역할 프로비저닝 서비스) 사양을 지원합니다. 학습자가 외부 학습 관리 시스템(플랫폼)에서 Learning Manager를 시작하면 Learning Manager는 플랫폼에서 학습자의 멤버십 기록을 검색합니다. 그런 다음 해당 레코드의 부서 또는 직원 ID와 같은 사용자 정의 속성을 활성 필드로 학습자의 프로필에 복사합니다.

## 사용 사례

* **학습자 프로필을 자동으로 개선합니다.** 데이터를 수동으로 입력하거나 별도로 가져오지 않고도 부서, 직원 ID 또는 사용자 정의 메타데이터 등의 속성을 플랫폼에서 Learning Manager로 가져올 수 있습니다.
* **학습자의 출처를 분석합니다.** 국가 및 도시와 같은 위치 속성을 캡처하여 학습자의 출신 지역을 그립니다. Learning Manager에서 결과 프로파일 필드를 분석에 사용합니다.
* **프로필 데이터를 원본 플랫폼에 맞게 정렬합니다.** 플랫폼은 여전히 진실의 근원으로 남아 있다. Learning Manager는 학습자가 시작될 때마다 값을 새로 고칩니다.
* **하나의 계정에서 여러 플랫폼을 지원합니다.** 네임스페이스 접두사는 플랫폼이 동일한 속성 이름을 사용하는 경우에도 다른 플랫폼의 속성을 별도로 유지합니다.

Learning Manager는 NRPS 사용자 정의 필드 동기화를 통해 실행 시 다음을 수행합니다.

1. 플랫폼이 NRPS를 지원하는지 검색합니다.
2. 플랫폼에서 학습자의 멤버십 실행 기록을 요청합니다.
3. 해당 레코드에서 사용자 지정 특성을 추출합니다.
4. 학습자 프로필에 속성을 활성 필드로 작성합니다. 각 필드 이름에는 `<namespace>` 접두어가 포함되어 있으므로 다른 플랫폼의 특성이 충돌하지 않습니다.
5. Learning Manager는 AGS(할당 및 등급 서비스)에 이미 사용하고 있는 OAuth 2.0 클라이언트 자격 증명 토큰을 다시 사용합니다. 새 토큰 끝점을 구성할 필요가 없습니다.

>[!NOTE]
>
>NRPS는 LTI Advantage의 선택적 사양입니다. NRPS 및 사용자 정의 속성에 대한 지원은 플랫폼에 따라 다릅니다. 이 기능을 사용하려면 먼저 플랫폼에서 NRPS 2.0을 노출하는지 확인하십시오.

## 주요 기능

* **NRPS 클레임 지원:** Learning Manager는 NRPS 클레임에 대한 모든 LTI 1.3 실행을 확인합니다. 클레임이 없을 경우 오류는 물론 학습자에게 영향을 주지 않고 시작이 정상적으로 계속됩니다.
  * 이 클레임은 다음 정보를 제공합니다.
    * **구성원 끝점:** `context_memberships_url `학습자가 ALM을 시작한 과정 또는 학습 컨텍스트의 서비스 URL을 식별합니다.
    * **지원되는 버전:** `service_versions`은(는) 해당 끝점에서 사용할 수 있는 NRPS 버전을 나열합니다.
      이 기능은 NRPS 2.0을 지원합니다.
  * **공유 토큰 인프라:** Learning Manager는 기존 AGS 토큰 요청에 NRPS 범위를 추가하고 기존 등록당 토큰 캐시를 다시 사용합니다.
* **사용자 지정 매개 변수를 학습자 프로필에 동기화**
  * **네임스페이스 접두사가 있는 활성 필드:** 각 사용자 지정 특성은 이름이 `<namespace>_<field_name>`인 활성 필드에 매핑됩니다.
  * **자동 필드 만들기:** 일치하는 활성 필드가 없으면 Learning Manager에서 **텍스트** 유형 및 **활성** 상태의 활성 필드를 만듭니다.
  * **진실의 원본인 플랫폼:** Learning Manager가 기존 프로필 값을 플랫폼의 최신 값으로 덮어씁니다. 학습자와 책임자는 이 필드를 편집할 수 없습니다.
  * **차단 해제 동작:** NRPS 오류로 인해 학습자가 학습 콘텐츠를 시작할 수 없습니다.
  * **사용자 지정 특성에 대한 여러 소스:** Learning Manager는 NRPS 엔드 포인트 및 LTI 시작 토큰의 사용자 지정 매개 변수에서 사용자 지정 특성을 읽을 수 있습니다. [시작 토큰의 사용자 지정 특성](#custom-attributes-in-the-launch-token)에 대해 자세히 알아보세요.

## 지원되는 구성

| 항목 | 지원 |
|----------------------------------------------------------------|--------------------------------------------------------------------------|
| Learning Manager 역할 | LTI 1.3 도구 |
| LTI 버전 | LTI 1.3 |
| NRPS 서비스 버전 | 2.0 |
| 플랫폼(사양 호환 사용자 정의 필드 형식) | 무들, D2L Brightspace, Blackboard(앤솔러지), Sakai |
| 사용자 정의 필드 유형 | 텍스트 |
| 트리거 | 각 LTI 1.3 출시 |

플랫폼 지원은 NRPS 멤버 레코드에 사용된 사용자 정의 필드 직렬화 패턴에 따라 달라집니다. 여러 패턴이 공존할 수 있지만 Learning Manager는 활성 릴리스에서 지원되는 패턴만 처리합니다.

## 작동 방식

### 플로우 실행

1. 학습자가 플랫폼에서 Learning Manager를 실행합니다.
2. Learning Manager는 LTI 1.3 시작 토큰으로 NRPS 클레임을 읽습니다. 클레임에 NRPS 서비스 버전 2.0이 나열되면 Learning Manager는 세션 및 LTI 컨텍스트(강의)에 대한 `context_memberships_url`을(를) 저장합니다.
3. Learning Manager에서 NRPS 범위 `https://purl.imsglobal.org/spec/lti-nrps/scope/contextmembership.readonly`을(를) 포함하는 액세스 토큰을 요청합니다.
4. Learning Manager에서 전달자 토큰으로 `context_memberships_url?rlid=<lti_user_id>`을(를) 호출하여 시작된 학습자의 레코드를 검색합니다. 플랫폼에서 `rlid` 필터를 무시하고 전체 명단을 반환하면 Learning Manager는 `user_id`까지 학습자를 찾습니다.
5. Learning Manager는 레코드에서 사용자 정의 필드를 추출합니다.
6. Learning Manager는 각 사용자 정의 필드를 활성 필드에 매핑하고 학습자 프로필에 값을 작성합니다.
7. 또는 사용자 정의 매개 변수가 ALM 식별 가능 필드 `ALMfield`에서 미리 수정된 경우, ALM은 도구 실행 중에 학습자 프로필에 동기화될 사용자 정의 매개 변수를 추출할 수도 있습니다.

### 사용자 정의 필드 형식

NRPS 2.0 사양은 사용자 지정 데이터를 멤버 레코드에서 `message` 배열로 정의합니다. Learning Manager는 해당 배열 내의 LTI 사용자 정의 클레임에서 사용자 정의 데이터를 읽습니다. 이번 릴리스에서 Learning Manager는 사양 호환 패턴 S 표현을 지원합니다.

```json
{
  "user_id": "abc123",
  "message": [
    {
      "https://purl.imsglobal.org/spec/lti/claim/custom": {
        "department": "Engineering",
        "employee_id": "E4567"
      }
    }
  ]
}
```

### 시작 토큰의 사용자 정의 속성

플랫폼은 LTI 론칭 토큰에서 사용자 정의 속성을 사용자 정의 파라미터로서 전송할 수도 있다. Learning Manager는 시작 토큰과 NRPS 끝점 모두에서 특성을 수집하고 학습자 프로필에 저장합니다.

시작 토큰에 있는 특성의 경우 매개 변수 이름은 Learning Manager에서 요구하는 접두어 `almfield-`으로 시작해야 합니다. 접두어가 없으면 Learning Manager는 이러한 매개 변수를 다른 사용자 정의 매개 변수와 구별할 수 없으며 해당 매개 변수를 가져오지 않습니다. NRPS 끝점에서 검색된 특성에는 이 접두사가 필요하지 않습니다. 이 접두사는 ALM용 시작 토큰으로 사용자 정의 매개 변수를 가져와 학습자 활성 필드와 동기화해야 하는 필드를 식별하는 경우에만 필요합니다.

>[!NOTE]
>
>플랫폼에서 사용자 정의 매개 변수를 구성하기 전에 Learning Manager 담당자와 정확한 필수 접두어를 확인하십시오.

### 활성 필드 이름 지정 및 매핑

Learning Manager는 활성 필드 이름을 `<namespace>_<field_name>`(으)로 빌드합니다. 예를 들어, `https://purl.imsglobal.org/spec/lti/claim/custom` 네임스페이스의 `department` 필드는 `https://purl.imsglobal.org/spec/lti/claim/custom_department`이(가) 됩니다.

Learning Manager는 다음 규칙을 적용합니다.

* **이름 길이:** 이름이 활성 필드 이름 문자 제한을 초과하면 Learning Manager에서 먼저 네임스페이스 부분을 줄여서 필드 이름을 유지합니다.
* **이름 충돌:** 줄인 후 Learning Manager에서는 다른 소스의 기존 활성 필드와의 충돌을 확인합니다. 충돌이 있는 경우 고유한 이름을 찾을 때까지 단축 길이를 조정합니다. 고유한 이름을 찾을 수 없으면 필드를 건너뛰고 오류를 기록합니다.
* **일치:** 필드 이름 일치는 대/소문자를 구분하지 않습니다.
* **기존 및 사용 필드:** Learning Manager는 학습자 프로필에 값을 기록합니다.
* **기존 및 비활성화된 필드:** Learning Manager에서 오류를 기록하지 않고 필드를 건너뜁니다.
* **기존 필드 없음:** Learning Manager는 **활성** 상태의 **텍스트** 필드를 만듭니다.

### 프로필에 값 쓰기

* Learning Manager가 NRPS 데이터를 검색할 때마다 모든 확인된 사용자 정의 필드 값을 시작 학습자의 프로필에 기록합니다. 다른 학습자 프로필은 변경되지 않습니다.
* 필드에 이미 값이 있는 경우 Learning Manager는 플랫폼의 최신 값으로 필드를 덮어씁니다.
* 플랫폼 값이 비어 있거나 null이면 Learning Manager는 기존 프로필 값을 유지합니다.
* 한 필드를 작성하지 못해도 시작이나 다른 필드에 대한 쓰기가 차단되지 않습니다.
* Learning Manager는 가능한 경우 동일한 시작 트랜잭션에서 필드 업데이트를 적용합니다.
* 학습자는 프로필 페이지에서 NRPS 원본 필드를 편집할 수 없으며 관리자는 학습자 대신 이러한 값을 편집할 수 없습니다.

## NRPS 사용자 정의 필드 동기화 설정

### 사전 요구 사항

* 플랫폼이 Learning Manager에 LTI 1.3 도구로 등록되었습니다. 이 기능은 LTI 1.1 또는 LTI 1.2를 지원하지 않습니다.
* 사용 중인 플랫폼은 NRPS 서비스 버전 2.0을 지원하며 사양 호환 `message` 형식으로 사용자 지정 특성을 표시합니다.
* LTI 시작 토큰에 `namesroleservice` 클레임이 포함되어 있습니다.
* 클레임은 과정별 NRPS 끝점을 식별하는 `context_memberships_url`을(를) 제공합니다.
* 클레임의 `service_versions` 값은 `2.0`을(를) 포함합니다.
* 플랫폼의 도구 등록에 대한 관리자 액세스 권한이 있습니다.

### Learning Manager에 NRPS 범위 부여

NRPS 범위를 포함하는 새 등록에는 Learning Manager에서 추가 구성이 필요하지 않습니다.

NRPS 범위가 포함된 새 등록은 Learning Manager에서 더 이상 변경되지 않고 작동합니다. 기존 등록의 경우 플랫폼 관리자는 플랫폼 측에서 도구 등록을 업데이트해야 합니다.

>[!NOTE]
>
>Learning Manager에서 토큰 끝점, 클라이언트 ID 또는 개인 키를 변경할 필요가 없습니다. 기존 AGS 구성이 재사용됩니다. 플랫폼에서 NRPS 범위를 부여하지 않는 경우 Learning Manager는 AGS 또는 시작에 영향을 주지 않고 NRPS를 건너뜁니다.

### 플랫폼에 학습자 속성 노출

플랫폼은 공유하는 학습자 속성을 제어합니다. 정확한 단계는 플랫폼에 따라 다릅니다. 예를 들어, Moodle에서는

1. LTI 1.3을 사용하여 Learning Manager를 외부 도구로 추가합니다.
2. 플랫폼에서 학습자 정보를 도구와 공유할 수 있는 개인 정보 설정을 활성화합니다.
3. 보내려는 사용자 정의 속성을 정의합니다. 플랫폼 변수나 미리 정의된 값을 사용할 수 있습니다.
4. 또한 시작 토큰에서 속성을 사용자 정의 매개 변수로 보내는 경우, Learning Manager에서 요구하는 접두어를 각 매개 변수 이름에 추가합니다.

>[!NOTE]
>
>학습 사용 사례에 필요한 속성만 표시합니다. Learning Manager는 플랫폼을 진실의 근원으로 취급하며 이 릴리스에서는 별도의 동의 또는 개인정보 제어 기능을 제공하지 않습니다.

### 동기화 확인

1. 테스트 학습자로 플랫폼에서 Learning Manager를 실행합니다.
2. 실행이 정상적으로 완료되는지 확인합니다.
3. Learning Manager 책임자 앱에서 활성 필드 페이지를 엽니다.
4. **텍스트** 유형과 **활성** 상태로 네임스페이스 접두사와 함께 필드가 표시되는지 확인합니다.
5. 테스트 학습자의 프로필을 열고 값이 플랫폼과 일치하는지 확인합니다.
6. NRPS 소스 필드가 읽기 전용인지 확인합니다. 학습자나 책임자는 동기화된 값을 수동으로 편집할 수 없습니다.
7. 비어 있지 않은 소스 값을 변경한 후 다시 실행하고 Learning Manager가 기존 프로필 값을 최신 NRPS 값으로 덮어쓰는지 확인합니다.

>[!TIP]
>
>필드가 있지만 비활성화되어 있는 경우 Learning Manager에서 해당 필드에 쓰지 않습니다. 필드를 채우려면 해당 필드를 활성화합니다.

## 오류 처리 및 로깅

Learning Manager는 NRPS 문제로 인해 학습자를 차단하지 않습니다. 다시 시도하지 않습니다. 오류를 기록하고 해당 실행에 대한 NRPS 동기화를 건너뜁니다. 다음 번 실행이 다시 시도됩니다.

| 조건 | 결과 |
|------------------------------------------------------------------|-------------------------------------------------------|
| 시작 토큰에 NRPS 클레임이 없습니다. | NRPS를 건너뜁니다. 시작은 계속됩니다. |
| NRPS 서비스 버전 1.0만 있음 | NRPS를 건너뜁니다. 시작은 계속됩니다. |
| 토큰 요청이 실패하거나 플랫폼에서 NRPS 범위를 허용하지 않음 | NRPS를 건너뜁니다. AGS 및 시작은 영향을 받지 않습니다. |
| NRPS 호출 실패(시간 초과, 4xx 또는 5xx) | 오류가 기록됩니다. 시작은 계속됩니다. |
| NRPS 응답에서 학습자를 찾을 수 없음 | 필드 동기화를 건너뜁니다. 시작은 계속됩니다. |
| NRPS 응답에 사용자 정의 필드가 없습니다. | 오류 없이 필드 동기화를 건너뜁니다. |
| 필드 이름 충돌을 해결할 수 없습니다. | 필드를 건너뛰고 오류가 기록됩니다. |
| 단일 필드 쓰기가 실패함 | 다른 필드는 계속 기록됩니다. 시작은 계속됩니다. |

각 로그 항목에는 타임스탬프, 플랫폼 등록 ID, 학습자 ID 및 실패 이유가 포함됩니다. Learning Manager 시스템 관리자는 로그에 액세스할 수 있습니다.

## 노트

* 시작하는 학습자의 기록만 동기화됩니다. Learning Manager는 전체 강의 목록을 동기화하지 않습니다.
* NRPS 서비스 버전 2.0만 지원됩니다.
* 동기화된 모든 필드의 형식은 **텍스트**&#x200B;입니다. Learning Manager는 값에서 유형을 유추하지 않습니다. 숫자, 날짜 및 부울 필드 유형은 지원되지 않습니다.
* Learning Manager는 LTI 도구 역할을 합니다. NRPS 플랫폼으로 작동하지 않으며 다른 도구에 명단 끝점을 제공하지 않습니다.
* 사용자 정의 필드 동기화는 LTI 시작 중에 발생합니다.
